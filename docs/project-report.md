# 基于3D Gaussian Splatting的中小型静态场景重建与Web可视化系统项目阶段报告

## 一、项目定位与当前边界

本项目的毕业设计题目为“基于3D Gaussian Splatting的中小型静态场景重建与Web可视化系统设计与实现”。项目定位为应用型三维重建系统：面向单管理员的本地工作站，将多视角影像预检、COLMAP 相机位姿估计、3DGS 训练、质量评价、模型版本管理和 Web 交互浏览整合为可管理的流程。

当前系统的输入为普通相机、手机或无人机采集的、具有足够重叠度的静态场景照片。无人机影像是本阶段的验证数据来源，而非系统唯一输入。GPS 信息仅作为可选的元数据展示或后续地理配准参考，不作为 COLMAP 或 3DGS 重建的必要条件。

项目首版明确限定如下：

- 采用本地单工作站、单管理员和串行训练任务；
- 训练计算计划在配备 RTX 4060 Laptop GPU 的 Windows 工作站完成；
- Web 端用于已发布结果的交互浏览，后期可选部署至 NAS；
- 不涉及公网开放训练、多用户 GPU 调度、动态场景、城市级重建、精确测量、网格编辑或 3DGS 核心算法改进。

## 二、验证数据与数据准备

### 1. 无人机照片整理与元数据检查

已使用一组 DJI 无人机影像进行前置流程验证。原始数据目录记录为 `testphoto1`，共 50 张 JPG 照片，影像分辨率为 4032 × 3024，相机型号为 DJI FC3582，焦距记录为 6.72 mm。照片中包含 GPS 纬度、经度和高度等 EXIF/XMP 元数据，已导出为 `exif_summary.csv`；原始照片未被修改。

本阶段已检查的元数据包括：文件名、拍摄时间、图像宽度和高度、相机厂商与型号、焦距及 GPS 信息。上述检查用于数据整理和输入质量分析，不能替代后续对图像清晰度、视角覆盖、曝光稳定性和场景静态性的评估。

### 2. 数据适用性说明

该组影像用于验证多视角重建前处理的可行性，不能据此概括所有场景均可稳定重建。反光或透明材质、大面积无纹理区域、运动物体、天空占比过高、视角覆盖不足及强曝光差异，均可能导致特征匹配、位姿估计或后续 3DGS 训练效果下降。

## 三、已完成的技术验证

### 1. COLMAP 特征提取、匹配与稀疏重建

已使用带 CUDA 支持的 COLMAP 完成以下流程：

- SIFT 特征提取；
- 图像特征匹配与几何验证；
- 增量式 SfM（Structure-from-Motion）重建；
- 相机位姿估计与稀疏三维点云生成。

### 2. COLMAP 重建结果

最终有效结果记录于 `colmap_run_02`：

- 注册图像：50 / 50；
- 相机数量：1；
- 稀疏三维点数量：39,638；
- 观测数量：324,538；
- 平均轨迹长度：8.19；
- 每张图像平均观测数：6,490.76；
- 平均重投影误差：0.748316 像素。

上述结果表明，该组 50 张影像已成功参与同一个稀疏重建模型，图像匹配和相机位姿估计流程能够正常完成。重投影误差仅反映该 SfM 模型内部的像素拟合情况，不能单独证明后续 3DGS 的视觉质量、几何精度或 Web 端性能。

### 3. 稀疏点云导出

已将 COLMAP 稀疏模型转换为 PLY 格式点云：`colmap_run_02/sparse.ply`。该文件可使用 CloudCompare 查看，用于检查稀疏点云的空间形状与重建范围。该点云属于 SfM 前置结果，不等同于 3DGS 训练产物或规则网格模型。

### 4. GPU 深度学习环境准备

已创建 Conda 环境 `nerfstudio`，Python 版本为 3.10，并完成 CUDA 11.8 版 PyTorch 与 GPU 可用性验证：

- PyTorch：`2.7.1+cu118`；
- CUDA 可用：`True`；
- GPU：NVIDIA GeForce RTX 4060 Laptop GPU；
- 显存：约 8 GB。

该验证表明本机具备执行后续 GPU 训练任务的基础条件，但不等同于 Nerfstudio Splatfacto 已完成训练或整体工具链已经验证成功。

### 5. Splatfacto 首次启动验证（2026-09-07，未成功，已弃用原因）

已使用 `ns_try`（cu118）环境尝试执行 5,000 迭代 Splatfacto 训练，在第 1 次训练迭代调用 gsplat CUDA 后端时退出。真实根因经多层排查后确定为：**gsplat 1.4.0 需要 CUDA 12+ 的 CUB 库，而 cu118 环境自带 CUDA 11.8 的 CUB 过旧**，与 gsplat 1.4.0 不兼容（并非单纯的 cl.exe 未进环境，那只是第一层表象）。该 cu118 环境已弃用。

### 6. Splatfacto 烟雾训练成功（2026-09-08）

改用 **ns_cu128 环境（CUDA 12.8）**，gsplat 1.4.0 的 CUDA 扩展 JIT 编译成功（CUB 兼容问题解决），随后执行 5,000 迭代 Splatfacto 训练**完整成功**：
- 达到 step 4999（99.98%），显示 `Training Finished`；
- 迭代时间约 18ms，Train Rays/sec 约 43M/s；
- 产物位于 `outputs\nerfstudio_data\splatfacto\2026-09-08_091637\`，含 `config.yml` 与 `step-000004999.ckpt`（约 174MB）。

该次训练证明「影像 → COLMAP → Splatfacto」的 3DGS 训练链路在本机（RTX 4060 Laptop 8GB）已打通。注：5,000 迭代为烟雾测试，用于验证通路，不构成最终质量结果。

### 7. 模型渲染验证通过（2026-09-08）

对烟雾模型的 5 张留出测试视角执行 `ns-render dataset` 渲染成功（12 fps），产物含 rgb 重建图 / gt-rgb 原图 / depth 图，位于 `outputs\render_ds\test\`。项目负责人目测：**重建图与原图接近、观感近实拍**，表明训练模型能对邻近的留出视角重建出新视图。至此「影像 → COLMAP → Splatfacto → checkpoint → 渲染新视角」的链路已验证。注：该观感基于单一航拍场景且测试视角与训练视角高度相邻，仅作通路验证，不作普遍性质量结论。

## 六、分级交付目标与验收优先级

为控制本科毕业设计的实现范围，后续工作按对项目成立程度和答辩价值分为三级。等级表示交付优先级，不表示技术难度。

### 一级：项目成立的必要交付（保底线）

一级功能未完成，项目不能形成“基于 3DGS 的重建与 Web 可视化系统”的完整闭环：

1. 使用具有足够视角重叠度的静态场景照片作为输入；
2. 通过 COLMAP 获得相机位姿和稀疏点云；
3. 将 COLMAP 结果接入 Nerfstudio Splatfacto，至少完成一个场景的 3DGS 训练；
4. 导出训练结果，并在本地浏览器中实现模型加载、旋转和缩放查看；
5. 保存照片来源、训练配置、软件版本、随机种子、模型文件和关键指标，形成可复现的最小实验记录；
6. 提供能够完成模型加载、旋转和缩放的最低可演示界面。

一级最低验收链路为：

`真实照片 → COLMAP → Splatfacto → 模型导出 → 浏览器交互查看 → 实验记录`

### 二级：开题承诺兑现线（必须优先完成）

一级链路稳定后，优先完成以下增强内容：

二级不是可有可无的扩展，而是开题报告中实验和系统目标的主要兑现内容。一级完成后，应优先完成以下工作：

1. 固定训练集与测试集、COLMAP 结果、图像分辨率、随机种子、软硬件版本，比较快速、标准和高质量三档训练迭代预算下的结果；
2. 记录 PSNR、SSIM、LPIPS、训练耗时和模型大小等主要指标；
3. 提供轻量的本地任务管理入口，支持选择照片目录和训练档位、启动任务、查看状态与日志；
4. 保存训练参数、任务状态、指标和模型路径，形成简单的模型版本记录；
5. 在条件允许时使用两类中小型静态场景进行验证，并分析拍摄条件对结果的影响。

二级功能用于证明系统具有可重复的实验流程和基本的应用管理能力，不要求实现复杂权限、审批流或多用户调度。

### 失败降级方案

关键工具出现兼容性或资源问题时，优先保证一级闭环，不因扩展功能阻塞项目：

- Splatfacto 或其依赖无法在当前环境稳定运行时，在独立 Conda 环境中按兼容版本重新安装；仍无法运行时，记录原因并降级为可用的 gsplat 或原版 3DGS 训练实现；
- 8 GB 显存不足时，降低输入分辨率、减少训练迭代或限制高斯数量，保留至少一个可完成训练的场景；
- 自研 Three.js 查看器出现兼容问题时，先使用 Nerfstudio 自带的 Web 查看器完成浏览器演示，再将自研查看器列为后续改进；
- 多场景实验无法按计划完成时，先完成一个主场景的三档对照，并将第二场景作为补充验证，不虚构实验结果。

4. 交付物是否满足当前阶段的验收标准；
5. 是否遗漏异常情况、隐性成本和后续工作量。

DeepSeek Harness不直接替代 CodeX 编写项目代码，也不以未经验证的建议作为项目事实。

### 3. 协同工作流程

每个阶段按照以下顺序执行：

1. CodeX 提交阶段目标、实施内容和验收标准；
2. CodeX 完成可执行任务并保存产物和日志；
3. CodeX 更新本报告，标注“已完成”“部分完成”“未完成”或“阻塞”；
4. 项目负责人将阶段结果和报告变更交给 DeepSeek Harness 审查；
5. DeepSeek Harness按“事实核对、技术风险、范围风险、文案风险、修改建议”格式反馈；
6. CodeX 对意见逐条回复并实施必要修正；
7. 项目负责人确认后，进入下一阶段。

### 4. 审查触发点

以下节点必须进行 DeepSeek Harness 审查：

- 一级闭环环境配置完成后；
- 首次 Splatfacto 训练成功或失败后；
- 模型导出与浏览器查看完成后；
- 三档训练实验完成后；
- 轻量任务管理功能完成后；
- 论文实验数据和系统截图整理完成后。

一般性的命令重试、格式调整和同一问题的局部修复，可由 CodeX 直接处理，并在下一次阶段更新中汇总。

### 5. 记录原则

阶段报告只记录可核验内容：执行日期、环境版本、输入数据、命令或脚本、输出文件、指标、错误信息和验收结论。DeepSeek Harness 的意见只有在完成核实或修改后，才可写入“已解决”；仍未验证的内容必须保留为风险或待办事项。每个触发点的原始诉求、CodeX响应、DeepSeek Harness原始意见和状态另行记录在 `审查记录.md` 中。
